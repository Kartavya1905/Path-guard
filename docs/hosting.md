# Free public hosting (Render + Neon)

PathGuard can run online at $0 as a **public demo**:

- **Render** (free web service) runs one container from the root `Dockerfile`. It builds the web app and serves it from the API, so everything is at one URL.
- **Neon** (free Postgres) stores the data.

Neither should ask for a card on the free plans. If either one asks for payment details, stop and don't enter them.

## What visitors get

- **Visitor identity:** each browser gets its own anonymous account in a signed, HttpOnly cookie (`PATHGUARD_VISITOR_IDENTITY_ENABLED=true`). Visitors only see projects they created. This isn't a login: clearing cookies or switching browsers starts a fresh, empty account.
- **Expiry:** projects untouched for 7 days are deleted (`PATHGUARD_VISITOR_RETENTION_DAYS`). Visitor accounts with nothing in them are deleted after a day. Cleanup runs on every start and whenever a project is created.
- **Limits:** 20 projects per browser, and request bodies up to 2 MB.
- **Starter examples:** each new visitor gets the two checkout examples, the launch with its baseline and checklist variant, and the transaction. Set `PATHGUARD_VISITOR_SEED_EXAMPLES=false` to turn this off.
- **Banner:** every page says it's a public demo and not for real or sensitive data.
- **No external processing:** external processing stays off, so no project data is sent anywhere else.
- **Free-plan limits:** Render's free service sleeps after about 15 minutes without traffic, so the first visit after that takes 30–60 seconds. Neon's free database also pauses when idle and wakes automatically.

## One-time setup

1. **Push the code to GitHub.** Render deploys from a GitHub repository, which can be private.
2. **Create the database on Neon:**
   1. Sign up at neon.tech (free plan) and create a project, for example `pathguard`, in the region closest to you.
   2. On the dashboard, open **Connect**.
   3. Copy the connection string. It looks like `postgresql://USER:PASSWORD@HOST/neondb?sslmode=require`. Use the **direct** connection, not the pooled one.
   4. Keep it private: it contains the database password.
3. **Create the service on Render:**
   1. Sign up at render.com (free plan) and connect your GitHub account.
   2. Choose **New → Blueprint** and pick the repository. Render reads `render.yaml`.
   3. When it asks for `PATHGUARD_DATABASE_URL`, paste the Neon connection string. PathGuard switches it to the psycopg driver itself.
   4. `PATHGUARD_SECRET_KEY` is generated by Render. Don't reuse it anywhere.
   5. Choose **Apply**. The first build takes a few minutes.
4. **Check it:**
   1. Open `https://<your-service>.onrender.com/api/health`. It should say `"status":"ok"` and `"identity":"visitor"`.
   2. Open the site itself and create a project.

After this, every push to the deployed branch redeploys automatically (`autoDeploy: true`).

## Settings used online

| Variable | Value | Why |
|---|---|---|
| `PATHGUARD_ENV` | `production` | Secure cookies; refuses the local demo identity |
| `PATHGUARD_DEMO_IDENTITY_ENABLED` | `false` | The shared local demo user is never used online |
| `PATHGUARD_VISITOR_IDENTITY_ENABLED` | `true` | Private anonymous account per browser |
| `PATHGUARD_SECRET_KEY` | generated | Signs visitor cookies (at least 32 characters) |
| `PATHGUARD_DATABASE_URL` | Neon string | `postgres://` and `postgresql://` URLs are accepted |
| `PATHGUARD_VISITOR_RETENTION_DAYS` | `7` | How long untouched projects are kept |
| `PATHGUARD_EXTERNAL_PROCESSING_ENABLED` | `false` | No project data leaves PathGuard |

## Try the hosted image locally

Run these from the repository root. The first command creates a separate database in the Compose Postgres. The last one starts the hosted image in production mode on port 8650.

```powershell
docker compose exec -T db psql -U pathguard -d postgres -c "CREATE DATABASE pathguard_hosted"
```

```powershell
docker build -t pathguard-hosted:local .
```

```powershell
docker run --rm -p 127.0.0.1:8650:10000 -e PORT=10000 -e PATHGUARD_ENV=production -e PATHGUARD_DEMO_IDENTITY_ENABLED=false -e PATHGUARD_VISITOR_IDENTITY_ENABLED=true -e PATHGUARD_SECRET_KEY=local-check-secret-key-0123456789abcdef -e "PATHGUARD_CORS_ORIGINS=[]" -e PATHGUARD_DATABASE_URL=postgres://pathguard:pathguard@host.docker.internal:26432/pathguard_hosted pathguard-hosted:local
```

Open http://127.0.0.1:8650. The browser tests also run against it:

```powershell
$env:PW_BASE_URL = "http://127.0.0.1:8650"; npm run test:e2e
```

## Before real (non-demo) use

Visitor identity is fine for a public demo, but it isn't authentication. Before real teams use the site, add a proper sign-in, as described in [security.md](security.md).
